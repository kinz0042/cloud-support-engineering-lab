# Career transition operating plan

Start: 29 October 2026. Initial planning assumption: 10 focused hours/week, approximately 24–32 weeks. This is a capacity estimate, not a hiring promise. Pace changes with baseline results; progress by gates. Give the learner one task at a time.

## Phases

| Phase | Approximate effort | Work and incidents | Gate |
|---|---:|---|---|
| Baseline / environment | 5–10h | Verify laptop/OS/tools; HTTP 401 observation; honest skill baseline | Explain request, response, status and evidence |
| Linux / network / Git | 30–40h | Permissions, processes, services, disk, ports, DNS, TCP/TLS, branches; broken service and DNS cases | Diagnose an unseen service/network fault and commit evidence |
| API / authentication | 40–50h | HTTP, REST, JSON, curl, Postman, API keys, OAuth2, JWT, pagination and rate limits | Reproduce 401/403/429/500; explain auth vs authorization; read code |
| PostgreSQL / application | 35–45h | SQL joins/aggregation, schema, migrations, connectors, locks, indexes and EXPLAIN | Diagnose connectivity and slow query with measured evidence |
| Containers / integrations | 40–50h | Docker/Compose networks, env vars, webhooks, HMAC, retries, idempotency and Python/Bash tools | Recover failed delivery without duplicate processing |
| Observability / cloud | 40–60h | Structured logs, metrics, traces, alerts; AWS IAM, S3, EC2, SG and CloudWatch | Correlate an incident and validate safe AWS remediation/teardown |
| Interviews / applications | 30–40h plus ongoing | Blind drills, customer writing, take-home, CV/LinkedIn, targeted pipeline | Pass readiness contract and role-specific checks |

Some work overlaps. Every week: two investigation sessions, one fundamentals block prompted by incident gaps, one evidence/write-up block, one short closed-book explanation. Teach missing concepts in small chunks, then retry without hints.

## Portfolio policy

One flagship first. At least 8 quality cases and reliable setup before adding projects. Add a separate API integration project only if external API/SDK depth is missing; add a cloud project only if it proves deployment/network skills absent from the flagship. A third repository is optional. No invented screenshots, measurements, completed incidents or badges.

For every major component learner explains purpose, design, failure modes, diagnostic commands and recovery. AI-generated changes get reviewed and explained before counting as learner evidence. Preserve unsuccessful hypotheses. Never backdate commits or manufacture contribution activity.

## Market feedback

Every two weeks during active training: review 10–15 distinct employer-hosted vacancies across at least 5 employers; deduplicate reposts. Record checked date, source, exact country/timezone wording, seniority, required/preferred skills, shifts, employment model, travel and unresolved eligibility. Report counts with denominator; small samples are directional.

Change priorities for a recurring requirement across at least 3 distinct relevant employers or a selected target role. Do not replace fundamentals each time a new tool appears. Kubernetes begins with logs/describe/events/services only if the evidence justifies it. Refresh again immediately before each application.

## Application strategy

Early targets: associate/junior technical, application, API and product support. Broader cloud/devtools support follows competence gates. Local/EMEA contract or SaaS support work can be a bridge; overseas employment is the goal, not the only acceptable first evidence.

Prioritize explicit worldwide/Africa/Nigeria roles; EMEA without country list is eligibility-unconfirmed until employer confirms Nigerian employment or contracting. Exclude explicit incompatible residency/work authorization. Track country, schedule, shift tolerance, contract/payroll route and travel constraints before tailoring.

Start with 5–8 carefully matched applications/week after readiness, adjusting to qualified supply. Track eligible → applied → screen → technical → offer; investigate conversion after 20 applications. Tailor CV to proven skills and real ISP responsibilities; verify duties and outcomes before claiming them. Lab work belongs under Projects. Practice one real troubleshooting story weekly. Do not claim CCNA certification.

Prepare remote-work reliability: power/internet backup, quiet call space and agreed coverage. Determine constraints without assuming equipment purchases. No recruiter outreach, applications or personal-data transmission without user authorization.
